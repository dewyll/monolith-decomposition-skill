# v0.2.0: measure what imports miss, and guard without going red on day one

This release closes the gaps found in a review of 0.1.0. The extractor
missed common Python imports, the approval gates relied on the agent's
discipline alone, and the CI guard could not be adopted by a real monolith
that starts out with cycles. Three new measurements cover what static
imports cannot see.

## Highlights

### Hidden coupling, measured
- **`change_coupling.py`** reads git history: churn per component and pairs
  that keep changing together. Pairs with no static dependency between them
  are flagged as hidden coupling.
- **`find_data_coupling.py`** finds shared tables from ORM mappings (ten
  frameworks) and SQL strings, and emits `database` edges from each user
  to the owning component. Pass `--schema` with your DDL to cut false
  positives.
- **`analyze_dependencies.py --extra-edges`** (or `dependencies.extra_edges`
  in `config.json`) merges those edges, or any hand-made runtime/event
  edges, into the analysis. The report says where each edge came from.

### A guard you can turn on today
- **Baseline ratchet**: `check_fitness.py --update-baseline` freezes the
  current cycles and edges. Existing cycles become warnings; a new or
  grown cycle fails F4.1, and **F4.4** fails on any new component
  dependency. Removing coupling and updating the baseline locks the gain in.
- **`run_guard.py`**: one command for CI that re-measures the code before
  checking it, so the guard sees the pull request rather than stale
  artifacts.

### Help with the hard decisions
- **Cut candidates** for every cycle: the lightest set of edges whose
  removal breaks it, a concrete starting point for the cycle RFCs.
- **`suggest_domains.py`**: deterministic Louvain clustering over imports
  plus co-change, with modularity and cohesion, as a measured first draft
  for Phase 5. It never writes `domains.json`; the business still decides.

### Gates enforced by the tooling
`state.py` refuses to start a phase before the previous one is approved, to
approve a phase whose RFCs are not Accepted, or whose latest fitness run
failed or predates the phase start. Phases 1–6 cannot start under tactical
forking. An override needs `--force --reason "..."` and is recorded in the
history.

## Fixes
- Python: imports are parsed with `ast`. Parenthesised multi-line imports
  (the black/isort style) previously produced **no edge at all**, and
  `import x  # comment` was ignored. Files that do not parse fall back to
  an improved regex scanner.
- All languages: commented-out imports and imports inside docstrings or
  strings are no longer counted. C/C++ includes are no longer counted twice.

**If you ran 0.1.0 on a Python codebase, re-run Phase 4.** The dependency
graph was a lower bound, often a much lower one, and cycles may have been
missed.

## Also new
- A complete worked example: `examples/tiny-monolith/decomposition` now
  goes through phases 0–6 with eight RFCs, a domain map, a service map with
  extraction order, a baseline and a green guard.
- Behaviour evals for `claude plugin eval` check that the agent stops at
  the gate, takes numbers from scripts, resumes without redoing work,
  does not refactor unasked and stays out of unrelated tasks.
- `SKILL.md` uses `${CLAUDE_SKILL_DIR}`; its description leads with the
  trigger phrases.
- New schemas: `change-coupling`, `data-coupling`, `domain-suggestions`,
  `baseline`.

## Upgrading
- Existing workspaces keep working; no artifact format changed
  incompatibly (`schema_version` stays 1).
- `state.py approve` is stricter. If an in-flight phase is refused, mark its
  RFCs Accepted and re-run `check_fitness.py --phase N`, or record the
  exception (an allow-list entry naming its RFC, or the baseline).
- To adopt the ratchet: after the Phase 4 RFC, run
  `check_fitness.py --update-baseline`, commit `fitness/baseline.json`, and
  replace your CI commands with `run_guard.py --workspace decomposition`.
